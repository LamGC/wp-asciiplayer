# wp-asciiplayer

把终端录屏放进 WordPress 文章和页面。添加 **Asciicast Player** 区块，就能一边编辑一边预览录屏；
旧文章里的 `[asciiplayer]` shortcode 也可以继续使用。

[English documentation](README.md)

## 安装

需要 **WordPress 6.3+** 和 **PHP 7.4+**。

1. 在 **插件 → 安装插件 → 上传插件** 中上传构建好的 `wp-asciiplayer.zip`。
2. 启用 **Asciicast Player**。

GitHub 下载的源码 ZIP 需要先构建，不能直接安装，步骤见[构建说明](SOURCE.md)。
[仓库 CI](.github/workflows/ci.yml) 列出了测试的环境组合；使用前也请检查与你的主题是否兼容。

## 添加录屏

1. 插入 **Asciicast Player** 区块。
2. 粘贴录制文件的 URL，或点击 **选择录制文件（Choose recording）**，从媒体库选择或上传 `.cast` 文件。
3. 停止输入约半秒后会自动加载预览。点击 **Apply URL** 可以立即加载，然后就能播放、暂停和拖动进度。
4. 在 **Display** 中设置宽度和对齐方式。可以选择预设，也可以填写 `480px`、`65%` 等 CSS 长度。
   播放器下方可以添加说明文字。
5. 在区块设置中调整主题、速度、循环、控制栏、适应方式、起始时间和空闲压缩，然后保存文章或页面。

重新打开文章时，已有有效 URL 的区块会自动加载录屏。编辑预览不会自动播放，即使你给前台启用了自动播放。
空白或无效 URL 不会发起请求。区块插入器里的示例是静态的，也不会请求录制文件。

### 展示宽度与终端尺寸

展示宽度决定播放器在页面里占多大空间，并且不会超出可用宽度。
调整宽度或使用 `fit: width` 只是缩放画面，不会改变终端的行列数。

**Columns** 和 **Rows** 留空时，会使用录屏本身的尺寸，并跟随录制中的尺寸变化。
需要手动设置时，可以使用区块工具栏或侧栏里的 **Terminal size**，两处设置会同步。
点击 **Use recording size** 可以清空手动设置，恢复录屏原有尺寸。

加载后，空白字段会显示录屏的原始行列数作为提示。换一个 URL 会刷新提示，但保留你手动填写的值。
提示只读取同一次预览响应的前 **64 KiB**；读取不到时保留通用占位提示，不猜测尺寸。
录制过程中后续的尺寸变化不会改变这组提示。

播放器自带样式，用来保持终端文字对齐和键盘焦点可见。部分主题可能仍需要调整 CSS。
播放操作和录屏隐私说明可以在侧栏的 **帮助（Help）** 面板中找到。

### 录制文件地址

URL 要直接指向录制文件，例如 `.cast` 文件，而不是 asciinema 分享页面。
其他域名上的文件需要允许来自你站点的 CORS 请求。HTTPS 页面可能无法加载 HTTP 文件，优先使用同站点的 HTTPS 地址。
插件不会代理请求或复制远程文件。

## 旧文章与 shortcode

旧文章可以继续使用原有 shortcode，不需要批量修改：

```text
[asciiplayer]https://example.org/demo.cast[/asciiplayer]
[asciiplayer theme="monokai" speed="1.5" controls="false"]https://example.org/demo.cast[/asciiplayer]
[asciiplayer startAt="2" idleTimeLimit="3" style="width: 80%;"]https://example.org/demo.cast[/asciiplayer]
```

布尔值、数值和旧的 camelCase 参数会自动处理。自定义 `style` 会经过 WordPress 的安全 CSS 过滤；
不安全的 URL、标记，以及可执行或对象形式的选项不会被接受。

支持的 shortcode 可以转换成区块，保存前请检查设置。插件不会自动重写旧文章。
经典编辑器仍可使用 shortcode，但没有专门的播放器编辑界面。

## 媒体库上传

已有 WordPress `upload_files` 权限的用户可以上传 `.cast` 文件。
多站点还需要网络管理员允许 `cast` 扩展名。插件不会增加用户的上传权限，也不会另建录屏管理文章类型。

上传文件会完整校验，限制如下：

- 每个文件最多 **32 MiB**。
- 最多 **100,000** 个事件或流内行。
- 每条 JSONL 行最多 **256 KiB**。
- 终端任一方向不超过 **1,000** 列或行。

旧的 asciicast v1 格式最多 **2 MiB**，需要格式化 JSON，并让起始 `{` 单独占一行；
内置播放器无法读取压成一行的 v1 文件。Asciicast v2、v3 使用标准 JSONL。
站点或服务器更低的上传限制仍然生效。无效录屏会被拒绝，也不会因此开放普通 JSON、HTML 或 SVG 上传。

## 界面语言

插件界面包含英文和简体中文（`zh_CN`）：

- 编辑器跟随 **用户 → 个人资料 → 语言**；未单独设置时使用站点语言。
- 前台跟随 **设置 → 常规 → 站点语言**。

翻译文件随 ZIP 附带，可离线使用。英文是默认回退语言，不需要单独的 `en_US` 翻译文件。
`zh_TW` 等其他中文地区设置不会自动映射成简体中文。

录屏中的终端内容和你填写的说明文字不会被翻译。
内置播放器自身的播放控件和帮助仍为英文，其文件保持上游原样。

## 资源与隐私

播放器的 JavaScript、CSS 和 WebAssembly 都在插件内，不会从 jsDelivr 加载。
插件没有统计追踪，也不会在后台调用远程 API。旧的 `ap_use_local_resources` 选项不再使用。

录屏文件会由浏览器直接请求你填写的 URL。外部主机可能收到读者的 IP 地址、浏览器请求信息，
以及浏览器和站点设置允许发送的来源信息。编辑预览也会发起同样的请求，包括重新打开已有录屏的文章时。

请使用可信主机，发布前检查终端录屏是否含有敏感信息。
外部主机适用自己的隐私政策，插件无法让外部录屏变成私有文件。
